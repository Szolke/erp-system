# 11. Assets

The sidebar's **Assets** menu item keeps a register of the company's physical assets: POS
terminals, mobile phones, printers, and anything else that has to be tracked item by item,
by serial number. The module can be enabled or disabled per company — if you don't see the
menu item, it isn't enabled for your company, or you don't have permission to access it.
Every asset belongs to the company you recorded it in; assets of other companies are not
visible.

## The Asset List

The list shows assets in name order, with the following columns:

| Column | Contents |
|---|---|
| Name | The identifier generated by the system (see below). Always visible. |
| Serial number | The serial number from the manufacturer. |
| IMEI | The IMEI identifier for mobile devices; `—` if there is none. |
| Asset type | Which type the asset belongs to (e.g. Mobile phone, Teya POS terminal). |
| Status | The asset's current state, shown as a coloured badge. |
| Actions | Edit and Delete buttons. Always visible. |

The columns can be customised with the **Columns** button above the list, and the page size
can be set as well — both work the same way as on the Documents list
([Chapter 4](04-documents.md)), and the system remembers your choice per user and per
company. The **Name** and **Actions** columns are locked: they cannot be hidden and cannot
be dragged to a different position.

The list **can also be sorted**: clicking a sortable column header cycles through the usual
three states (ascending → descending → default), as described in the same chapter. Your
chosen sorting is remembered along with the columns.

The search box above the list searches the **name, the serial number and the IMEI** at the
same time — a fragment is enough, you don't have to type the full identifier. The number of
matches appears below the table ("Total: N pcs"), with the pager underneath.

If you haven't recorded a single asset yet, the message *"No assets recorded yet."* appears
in place of the table.

## Adding an Asset

With permission to create assets, a **+ New asset** button appears in the top right corner
of the list. The form has three fields:

- **Serial number** — required. It must be unique within the company: if you already have
  an asset with that serial number, saving is rejected with an error message.
- **IMEI** — optional. If you fill it in, it must be unique within the company too.
- **Asset type** — required, selected from a dropdown. The list contains both the global
  types (available to every company) and the types your own company has added.

**You do not enter the name — the system generates it** at the moment of saving. The name
has three parts, separated by underscores: your company's prefix, the asset type's code,
and a five-digit sequence number. For example, at a company with the prefix `DEMO`, the
first asset of type code `TEYA` will be named `DEMO_TEYA_00001`, the next one
`DEMO_TEYA_00002`. Numbering runs separately per type, so the first asset with the code
`MOBIL` is created as `DEMO_MOBIL_00001`. The name is not shown on the creation form — it
appears only after saving.

> The prefix at the start of the name is the **sales group prefix** configured for the
> company ([Chapter 6](06-settings.md), Company Settings). If it is not filled in for your
> company, the asset cannot be created — set the prefix in Company Settings first.

After saving, the system takes you back to the asset list, where the new asset already
appears under its generated name.

## Editing an Asset

The **Edit** button in the list (with permission to edit assets) opens the detail page.
Four fields are shown here, but not all of them can be changed:

- **Name** — read-only. The generated identifier is permanently fixed after creation.
- **Asset type** — the dropdown is shown but disabled. The type cannot be changed later,
  because the name was derived from it.
- **Serial number** and **IMEI** — editable (the uniqueness rule applies here as well).
- **Status** — editable, chosen from the four states.

The bottom of the detail page shows who created the asset and who last modified it
([Chapter 8](08-other.md)).

---

## Statuses

An asset can be in one of four states. The status is **informational**: there is no
automatic behaviour behind it, you switch it manually as the asset's situation changes.

| Status | Meaning |
|---|---|
| Active | In use or in stock, in working order. |
| Issued | Handed out — with someone or at some location. |
| In service | Under repair. |
| Scrapped | Withdrawn from use. |

A new asset is always created in the **Active** state; this cannot be selected on the
creation form, only changed when editing.

---

## Deleting an Asset

The **Delete** button in the list (with permission to delete assets) asks for confirmation
and then permanently removes the asset. Deletion cannot be undone, and the freed sequence
number is not reused — the next asset receives the next number in line.

---

## Asset Types

The asset type provides the middle part of the asset's name, which is why an asset can only
be recorded against an existing type. Types are not maintained here but on the
**Settings → Asset Types** page — the list of global types, adding your own company type,
and the scope marker are described in [Chapter 6](06-settings.md).

---

## Permissions

Viewing, creating, editing and deleting assets are four separate permissions. If you only
have permission to view, the list opens but the **+ New asset**, **Edit** and **Delete**
buttons do not appear. Assigning permissions is described in
[Chapter 7](07-users-permissions.md).
